# A4PumpControl 0.2.0-beta.1

Status: **beta hardware-validation release candidate**

Future tag: `v0.2.0-beta.1` — this build process does not create the tag or publish a GitHub Release.

## Included capabilities

- shared Active Config;
- dual-pump flow calculations and quantized setpoints;
- port enumeration without opening ports;
- PROGRAM / ARM;
- process-safe START/STOP coordination;
- cancellable immediate and scheduled armed execution;
- fail-closed emergency target snapshots;
- NIS armed wrappers;
- commissioning, calibration, balance, and production preflight;
- Experiment Dashboard and recent-run history;
- sanitized diagnostics and traceable build identity.

## Required interpretation

The A4 protocol has no verified hardware readback. **PROGRAMMED — NOT READ BACK** means only that the command sequence completed without a reported transport error. `COMPLETED_ESTIMATED` means programmed time elapsed for the same persisted run; it is not physical completion.

Live speed or flow changes while a pump is running are unsupported. Local COM ports and Active Config paths must be configured. Physical direction, emergency STOP, measured flow, paired balance, NIS execution, display scaling, and microscope integration remain unvalidated until performed and recorded by an operator.

The Windows executables are unsigned. Verify the supplied SHA-256 and build manifest before installation.

## Installation

1. Verify `A4PumpControl-0.2.0-beta.1-win-x64.zip` against its `.sha256`.
2. Extract into a new versioned directory.
3. Copy or preserve the existing external `config`, `validation`, runtime, reports, and NIS logs using the documented upgrade helper.
4. Run `a4ctl\a4ctl.exe --version`.
5. Confirm `config-path`, `preflight`, and `validation-status`.
6. Complete the hardware-validation session before microscope experiments.
